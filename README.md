# Task-Specific NLP Pipelines versus Large Language Models

Code and results for the MSc thesis *Task-Specific Pipelines versus Large Language
Models for Cross-Lingual Text Analysis: A Comparative Study on German Newspaper
Discourse* (University of Trier, Department of Computational Linguistics, 2026).

The study compares three supervised NLP pipelines against four instruction-tuned
large language models on a corpus of 1,115 German newspaper articles about
sustainable building, published between 2015 and 2025.

## What the study found

The corpus was collected for this study and carries no annotations, so there is no
gold standard to evaluate against. Rather than adopt one system's output as the
reference, two consensus references were built, one from the agreement of each
system class, and every system was scored against both.

The main result is an inversion in inter-system agreement. On named entity
recognition the three pipelines agree substantially with one another
(Fleiss' kappa = 0.717) while the LLMs barely agree at all (0.103). On topic
classification the relationship reverses: the LLMs converge (0.774) while the NLI
pipelines scatter (0.274). Each class agrees with itself on exactly one of the two
tasks, and not the same one. This measurement uses no gold standard, so it is not
affected by the choice of reference.

Two further results follow. System rankings invert depending on which consensus
reference is used, so the two references are different targets rather than noisy
estimates of the same one. And giving an LLM German input instead of an English
translation improves NER by 0.114 F1, but a gap of 0.263 to the best pipeline
survives that correction, which places most of the difference in the architecture
rather than in the translation step.

## Notebooks

The notebooks are numbered in the order they were run. Each is self-contained: it
installs its own dependencies, mounts Google Drive, and reads from and writes to
the paths set at the top of the notebook.

| Notebook | Purpose |
|---|---|
| `00_setup_verification` | Check that libraries, models, and API access are available |
| `01_corpus_audit` | Load the raw corpus, deduplicate, fix encoding, report statistics |
| `02_preprocessing` | Language filtering, length filtering, sentence segmentation, translation |
| `03_ner_pipeline` | Run spaCy, Stanza, and Flair over the validation sample |
| `04_ner_llm` | Run the LLMs on the NER task |
| `05_ner_comparison` | Compare pipeline and LLM entity sets |
| `06_topic_modeling` | BERTopic run used to derive the category taxonomy |
| `06b_bertopic_fresh` | BERTopic re-run on fresh embeddings |
| `07_final_comparison` | Combined comparison across both system classes |
| `08_extended_analysis` | Per-label breakdowns and additional metrics |
| `09_llama70b_comparison` | Add the 70B model to the NER comparison |
| `10_error_analysis` | Inspect disagreements between systems |
| `11_ablation_german_input` | German versus English input, entity-set overlap |
| `12_integrity_check` | Verify reported numbers against the stored result files |
| `13b_en_de_comparison` | Translation ablation with F1 and significance testing |
| `14_dual_gold_standard` | Build both consensus references and score every system |
| `15_topic_classification` | NLI and LLM topic classification, agreement analysis |

## Data availability

The article texts are not included in this repository. They were collected from
newspaper archives under institutional access and a personal subscription, and
redistributing them would breach the terms under which they were obtained.

What is included is everything needed to check the analysis: the result summaries
in `Data/Processed/` hold the per-system predictions and metrics that every number
in the thesis is computed from, and `12_integrity_check` recomputes the reported
figures from those files.

## Reproducibility

The pipeline systems can be re-run as they are. Model versions are pinned in
`config.yaml`, decoding is deterministic, and the random seed is fixed at 42.

The LLM experiments cannot be re-run. All four models were served through the Groq
API, and all four were announced for deprecation by the provider in June 2026,
while this thesis was being written: `qwen/qwen3-32b` and
`meta-llama/llama-4-scout-17b-16e-instruct` were withdrawn on 17 July 2026, and
`llama-3.1-8b-instant` and `llama-3.3-70b-versatile` on 16 August 2026. The stored
predictions in `Data/Processed/` are therefore the only surviving record of those
runs, which is why the notebook outputs are committed rather than cleared. The
analysis remains reproducible from those files; the inference step that produced
them does not.

This turned out to be relevant to the thesis itself. The durability difference
between pinnable pipeline models and hosted LLM checkpoints is one of the
trade-offs the study set out to document, and it was demonstrated by events over
the course of a single Master's thesis.

## Environment

Experiments were run on Google Colab's free tier with the project mounted from
Google Drive. Each notebook installs what it needs in its first cell, so there is
no repository-level requirements file. The main dependencies are `spacy`
(`de_core_news_lg`), `stanza`, `flair`, `transformers`, `sentence-transformers`,
`bertopic`, and `groq`.
